## A3.1 统一坐标系

一切都在 **672 尺度像素**上表达：

```
672 token 宽 = 14 px
448 token 宽 = 21 px  (= 14 * 1.5)
```

两者共用一个线性坐标轴，不存在比例漂移。实现内部坐标一律 **×2**（672 token = 28，
448 token = 42），使所有权重都是整数，永不为浮点。

## A3.2 exclusion 按 **footprint 相交**判定（冻结）

```
E448(i, j)     = (i, j) 周围 3x3 的 448 token 块
excl_672(i, j) = 所有 footprint 与 E448(i, j) 相交的 672 token
```

**不得**写成硬编码的行列范围。E448 的物理跨度是 `[21(i-1), 21(i+2))`，
宽 `3*42 = 126` 缩放像素 = **4.5 个 672 token**。

精确结论（`v3_calibration.py` 合成测试逐条验证）：

> **长度恰为 4.5 token 的跨度，无论对齐与否，永远恰好交 5 个 token**
> —— 对齐时是 4 个完整 + 1 个半格；不对齐时是 3 个完整 + 2 个半格。

所以内部一个 448 的 3×3 块恰好排除 **5×5** 个 672 token，**不是 3×3**。
（曾误以为不对齐时会交 6 个；那是错误算术，已在测试中更正并记录。）

边界处 E448 会伸出图像，**只覆盖落在图像内的部分**，不做 padding。

## A3.3 672→448 用 **area-weighted pooling**（冻结）

```
sbar672(p) = sum_q |R448_p ∩ R672_q| * s672(q) / sum_q |R448_p ∩ R672_q|
```

一个 672 token 对该 448 patch 的**物理覆盖面积**越大，权重越大。
这样不存在"1 个还是 4 个 token""中心落在哪个格""rounding 往哪偏"这些隐含选择。

**若某个 448 patch 没有任何 672 token 覆盖 → fail-fast**，不自动补值。

## A3.4 必须说清楚的三条性质（避免后来者误判为 bug）

1. **pooling 是线性算子**，且**质量守恒**：
   `sum_p area_p * pooled_p == sum_q area_q * s672_q`。两者都精确成立。
2. **常数场被精确复现。**
3. **"线性场 pool 回自身"不成立，且不应期望它成立。**
   面积加权 pooling 平均的是 672 token 的**值**；一个被 448 patch
   部分覆盖的 token 仍然贡献它**完整中心**处的值，而不是被覆盖碎片的质心。
   例：某 patch 覆盖 token 0 的 28/42 与 token 1 的 14/42，斜率 2 的场给出
   `(28*1 + 14*3)/42 = 1.667`，而 patch 中心值是 `1.5`。这个差是**定义的
   后果**，不是缺陷。（曾把它当作正确性测试，属测试 bug，已更正。）
4. **跨边界的 spill 是正确行为**：一个横跨 448 边界的 672 token 按面积
   同时贡献给两侧。例如 4 个覆盖 token 全置 1 时，`pooled[patch] = 1.0`
   而总质量和为 `4*28^2/42^2 = 1.7778`。

## A3.5 仿射拟合（沿用 §2.4 / 补充 2 的方向）

```
s448_cal  ~=  a * s672_cal + b
```

**不得**因为另一方向 `R^2` 更高而临时倒置。必须记录
`a, b, R^2, n, RMSE, x_min/x_max, y_min/y_max`，并对
`a < 0`、`|a| > 100`、NaN/Inf **fail-fast，无 fallback**。

**已知真值测试（必须通过）**：构造 `s448 = 2*s672 + 0.3 + 微噪声`，
拟合须恢复 `a≈2, b≈0.3`；交换两个参数应得到 `a≈0.5`，证明拟合对方向敏感，
从而排除 x/y 写反、配对错位、flatten 顺序错误这一类"跑得动但语义反了"的 bug。
