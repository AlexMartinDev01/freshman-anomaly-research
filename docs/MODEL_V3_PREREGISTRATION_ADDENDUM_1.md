## A1.2 冻结的预算分配规则

**这不是事后调参，而是把 V3 的主张本身写成规则**：
在固定高分辨率预算下，把算力按需分配到需要细化的位置。
触发少 ⇒ 每个位置给更大上下文；触发多 ⇒ 每个位置给更小 crop。

### 预算

对每张测试图，设其全局 672 网格为 `(gh, gw)`，则

```
B = 0.5 * gh * gw          # 即 A2(full-672) token 数的一半，满足 G2 的 50% 上限
```

例：900×900 的 MVTec 图，672 网格 48×48 = 2304，故 `B = 1152`。

### 截断（修正原式在 m 很大时失效的问题）

**原式 `clamp(floor(sqrt(B/m)), 5, 33)` 有洞**：当 `m > floor(B/25)` 时，
即使取最小 crop 也超预算（例如 `B=1152, m=60` 时 `60*25 = 1500 > 1152`），
"G2 按构造成立"**不成立**。故先截断：

```
K_max = floor(B / 25)                      # 最小 crop 5x5 -> 25 token；B=1152 时 = 46
m'    = min(m, K_max)
```

若 `m > K_max`，**只保留 K_max 个窗口**，优先级（冻结，不引入任何新网络）：

```
1. hot 从高到低
2. hot 相同 -> gap 从低到高
3. 仍相同   -> 按 (row, col) 行优先的固定字典序
```

### crop 尺寸：预算内最大的**奇数**边

```
n = max{ q 是奇数 : 5 <= q <= 33,  m' * q^2 <= B }
```

取奇数是因为 crop 围绕触发窗口中心展开：`13`/`21`/`33` 有明确中心，
偶数边会产生半 token 对齐问题，没有必要自造几何歧义。

`B = 1152` 时的换算（与实测触发数对照）：

```
m'=1  -> n=33   (33^2      = 1089)
m'=2  -> n=23   (2*23^2    = 1058)
m'=4  -> n=15   (4*15^2    =  900)
m'=6  -> n=13   (6*13^2    = 1014)
m'=10 -> n=9    (10*9^2    =  810)
m'=20 -> n=7    (20*7^2    =  980)
m'=46 -> n=5    (46*5^2    = 1150)
```

**严格保证 `m' * n^2 <= B`，故 G2 的 token 部分按构造成立。**

### 边界情形

- `m = 0`：不细化，`A3 ≡ A0`。该图如实计为"未细化"，不特殊处理。
- `B < 25`：图太小，无法满足最小 crop，同样不细化并记录。

## A1.3 A4 / A5 必须逐图复制 A3 的 `(m', n)`

既然 A3 的 crop 尺寸逐图变化，A4/A5 就**不能只在总量上匹配预算**，而必须对
**每一张测试图**使用与 A3 **完全相同**的：

```
相同 crop 数量 m'  +  相同 crop 边 n  +  相同 token 预算 m' * n^2
```

**唯一允许的差别是 crop 的空间位置**：

- **A4 (random)**：在满足 `hot(W) >= tau_hot` 的窗口中均匀随机抽取 `m'` 个
  （A3 为 0 个时 A4 也为 0 个）。10 个预先固定的 seed，取均值。
- **A5 (oracle)**：用 GT 选 `m'` 个窗口。**diagnostic only**，不参与模型选择，
  不是 GO 必要条件。

这样 `A3 > A4` 才能纯粹解释为"**你的 selector 选的位置比随机位置好**"，
而不是"crop 几何不同"。

## A1.4 明确不由构造保证的部分

- **`wall-clock <= 70%` 必须实测**，不得声称由构造保证。crop/resize/写回
  的开销是真实的，测法见预注册 §6.2（冻结），且若 wall-clock 比值远差于
  token 比，必须如实说明。
- 本补充**不修改**预注册 §2.2.4 的任何阈值（`q=1/3`、`0.99`、`1/3`、
  3×3 窗口、stride 1），也不修改 §4 的任何 Gate 门槛。
